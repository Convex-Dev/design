# Convex Architecture Documents

Convex Architecture Documents (CADs) are the technical specifications for Convex and its ecosystem — the equivalent of Internet RFCs. They define the standards that implementations follow, so that applications and tools built on Convex remain compatible and interoperable.

Anyone can propose or develop a CAD. They are maintained openly in the [Convex-Dev/design](https://github.com/Convex-Dev/design) repository, and changes go through pull requests like any other part of the documentation. The Convex Foundation governs official acceptance, deciding when a CAD is formalised as a standard the ecosystem can rely on.

## Where to start

CADs are numbered in order of creation, so the numbering reflects history rather than importance. Good entry points:

- **[CAD000: Design Principles](/docs/cad/principles)** — the values behind the technical decisions
- **[CAD001: Convex Architecture](/docs/cad/arch)** — how the pieces fit together
- **[CAD003: Encoding Format](/docs/cad/encoding)** — the self-describing encoding used for every value
- **[CAD005: CVM Execution](/docs/cad/cvmex)** — the virtual machine
- **[CAD051: Convergent Proof of Stake](/docs/cad/cpos)** — the consensus algorithm

The full list is in the sidebar. CADs are reference documents and assume technical context; for narrative explanations of the same material, start with the [Overview](/docs/overview).
